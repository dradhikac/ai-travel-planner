# Phase 2 Data Contracts & Domain Specifications

This document defines the data contracts, validation rules, normalized provider models, itinerary structure, error catalog, and API specifications for Phase 2 of AI Travel Concierge.

---

## 1. Architectural Alignment & Conventions

- **Validation Library**: Pydantic v2 (leveraging `pydantic-settings~=2.16.0` and Python `3.11`).
- **Standardized Error Envelope**: All API error responses adhere to the uniform error shape established in Phase 1:
  ```json
  {
    "error": {
      "code": "error_code_string",
      "message": "Human-readable explanation",
      "details": []
    }
  }
  ```
- **Seams and Module Layout**:
  - Backend Pydantic Schemas: `backend/app/schemas/trip.py`, `backend/app/schemas/provider.py`
  - Backend Route Endpoints: `backend/app/api/routes/trips.py`
  - Backend Database Models: `backend/app/db/models/trip.py`
  - Frontend TypeScript Interfaces: `frontend/src/lib/types/trip.ts`, `frontend/src/lib/types/provider.ts`
  - Frontend Client Wrapper: `frontend/src/lib/api/trips.ts` consuming `frontend/src/lib/api/client.ts`

## 2. Provenance Taxonomy

To enforce truthfulness and prevent AI hallucinations from being masqueraded as verified ground truth, every data point carries a strict `Provenance` classification:

```python
from enum import Enum

class Provenance(str, Enum):
    RETRIEVED = "retrieved"
    GENERATED_SUGGESTION = "generated_suggestion"
    ESTIMATE = "estimate"
    UNKNOWN = "unknown"
```

- **`retrieved`**: Real facts fetched directly from external authoritative providers (e.g. Open-Meteo geocoding coordinates, official weather forecasts).
- **`generated_suggestion`**: Recommendations, descriptions, or itineraries generated by rule-based algorithms or LLM assistance.
- **`estimate`**: Computed approximations (e.g. estimated transit times or activity durations).
- **`unknown`**: Values that could not be determined or retrieved. Never fabricated or guessed.

## 3. Trip Intake Contract (`TripRequest`)

The intake contract validates user trip parameters before any external API calls or generation logic occur:

```python
from datetime import date
from decimal import Decimal
from enum import Enum
from typing import Literal
from pydantic import BaseModel, Field, field_validator, model_validator

ALLOWED_CURRENCIES = {"USD", "EUR", "GBP", "CAD", "AUD", "JPY", "INR", "CHF", "NZD", "SGD"}

class PacePreference(str, Enum):
    RELAXED = "relaxed"
    BALANCED = "balanced"
    PACKED = "packed"

class TripRequest(BaseModel):
    origin: str = Field(..., min_length=1, max_length=100, description="Departure city or location")
    destination: str = Field(..., min_length=1, max_length=100, description="Destination city or region")
    start_date: date = Field(..., description="Trip start date (ISO 8601)")
    end_date: date = Field(..., description="Trip end date (ISO 8601)")
    party_size: int = Field(default=1, ge=1, le=20, description="Number of travelers")
    budget_amount: Decimal | None = Field(default=None, gt=0, le=Decimal("10000000"), description="Total budget amount")
    currency: str | None = Field(default=None, description="ISO 4217 currency code")
    interests: list[str] = Field(default_factory=list, max_length=10, description="Up to 10 travel interests")
    pace: PacePreference = Field(default=PacePreference.BALANCED, description="Itinerary pace preference")

    @field_validator("origin", "destination", mode="before")
    @classmethod
    def strip_strings(cls, v: str) -> str:
        if isinstance(v, str):
            trimmed = v.strip()
            if not trimmed:
                raise ValueError("Location string cannot be empty or whitespace only")
            return trimmed
        return v

    @field_validator("interests", mode="before")
    @classmethod
    def normalize_interests(cls, v: list[str]) -> list[str]:
        if not isinstance(v, list):
            return []
        cleaned: list[str] = []
        seen = set()
        for item in v:
            if isinstance(item, str):
                norm = item.strip().lower()
                if norm and len(norm) <= 40 and norm not in seen:
                    seen.add(norm)
                    cleaned.append(norm)
        return cleaned[:10]

    @field_validator("currency", mode="before")
    @classmethod
    def validate_currency(cls, v: str | None) -> str | None:
        if v is None:
            return None
        norm = v.strip().upper()
        if norm not in ALLOWED_CURRENCIES:
            raise ValueError(f"Currency '{v}' is not supported. Allowed: {sorted(ALLOWED_CURRENCIES)}")
        return norm

    @model_validator(mode="after")
    def validate_contradictions_and_ranges(self) -> "TripRequest":
        # 1. Origin and destination contradiction
        if self.origin.lower() == self.destination.lower():
            raise ValueError("Origin and destination cannot be identical")

        # 2. Date order validation
        if self.end_date < self.start_date:
            raise ValueError("End date must be on or after start date")

        # 3. Maximum trip length (30 days maximum for Phase 2)
        trip_duration_days = (self.end_date - self.start_date).days + 1
        if trip_duration_days > 30:
            raise ValueError(f"Trip duration ({trip_duration_days} days) exceeds maximum limit of 30 days")

        # 4. Currency / Budget coupling
        if self.budget_amount is not None and self.currency is None:
            raise ValueError("Currency must be specified when budget_amount is provided")
        if self.budget_amount is None and self.currency is not None:
            raise ValueError("Currency cannot be specified without budget_amount")

        return self
```

## 4. Normalized External Provider Models

All third-party external data is normalized into uniform Pydantic models with clear source attribution:

```python
from datetime import datetime
from pydantic import BaseModel, Field

class SourceInfo(BaseModel):
    provider: str = Field(..., description="Provider name (e.g. 'Open-Meteo')")
    url: str = Field(..., description="Official provider URL")
    attribution: str = Field(..., description="Required attribution notice")
    fetched_at: datetime = Field(..., description="UTC timestamp of API request")
    data_origin: Literal["live", "mock"] = Field(..., description="Indicates live API vs fixture data")

class GeocodeResult(BaseModel):
    name: str = Field(..., description="Resolved location name")
    country: str = Field(..., description="Country name")
    admin_region: str | None = Field(default=None, description="State, province, or region")
    latitude: float = Field(..., ge=-90.0, le=90.0)
    longitude: float = Field(..., ge=-180.0, le=180.0)
    timezone: str = Field(default="UTC", description="IANA timezone name")
    source: SourceInfo
    fetched_at: datetime

class WeatherDay(BaseModel):
    date: date
    temp_min_c: float
    temp_max_c: float
    precipitation_probability_pct: int = Field(..., ge=0, le=100)
    precipitation_sum_mm: float = Field(..., ge=0.0)
    weather_code: int = Field(..., description="WMO weather interpretation code")
    condition_description: str = Field(..., description="Human-readable summary (e.g. 'Partly cloudy')")

class WeatherSummary(BaseModel):
    location: str
    days: list[WeatherDay]
    units: dict[str, str] = Field(default_factory=lambda: {"temperature": "celsius", "precipitation": "mm"})
    source: SourceInfo
    fetched_at: datetime
    data_origin: Literal["live", "mock"]
    horizon_note: str | None = Field(
        default=None,
        description="Notice if trip dates fall outside the 16-day forecast horizon"
    )
```

## 5. Itinerary & Response Contract

```python
from uuid import UUID
from pydantic import BaseModel, Field

class TimeOfDay(str, Enum):
    MORNING = "morning"
    AFTERNOON = "afternoon"
    EVENING = "evening"

class ItineraryItem(BaseModel):
    title: str = Field(..., min_length=1, max_length=150)
    time_of_day: TimeOfDay
    description: str = Field(..., max_length=500)
    provenance: Provenance = Field(default=Provenance.GENERATED_SUGGESTION)
    source_ref: str | None = Field(default=None, description="Optional citation or provider reference")
    note: str | None = Field(default=None, description="Helpful tip or scheduling note")
    cost_estimate: str | None = Field(
        default=None,
        description="Categorized purely as an estimate or unknown. Never claims real-time booking prices."
    )

class ItineraryDay(BaseModel):
    day_number: int = Field(..., ge=1)
    date: date
    items: list[ItineraryItem]

class Itinerary(BaseModel):
    days: list[ItineraryDay]
    summary: str = Field(..., max_length=500)

class TripResponse(BaseModel):
    id: UUID
    request: TripRequest
    itinerary: Itinerary
    weather: WeatherSummary | None = None
    sources: list[SourceInfo] = Field(default_factory=list)
    warnings: list[str] = Field(default_factory=list)
    created_at: datetime
```

## 6. Error Code Catalog & HTTP Status Mapping

All errors conform to the standard error shape:

| Error Code | HTTP Status | Trigger Condition | Error Message Example |
| :--- | :---: | :--- | :--- |
| `validation_error` | **422** | Contradictory inputs, dates in past, duration > 30 days | `"End date must be on or after start date"` |
| `destination_not_found`| **422** | Open-Meteo geocoding API returned 0 matching locations | `"Unable to geocode destination 'Xyz123'; verify location spelling."` |
| `provider_unavailable` | **503** | External API network timeout or connection refused | `"Weather service is temporarily unreachable; please try again later."` |
| `provider_rate_limited`| **503** | External API returned HTTP 429 Too Many Requests | `"External provider rate limit reached. Retry after 60 seconds."` (Includes `details: [{"retry_after": 60}]`) |
| `trip_not_found` | **404** | Trip ID does not exist in local database | `"Trip with id '...' was not found."` |
| `database_unavailable` | **503** | PostgreSQL connection pool exhausted or down | `"Database service is unavailable."` |

### Partial Failure Recovery Rule
- **Geocoding Failure**: Treated as a **fatal error** (HTTP 422). Coordinates are mandatory to anchor weather and destination planning.
- **Weather Service Failure**: Treated as a **graceful degradation** (non-fatal). If the weather provider is offline, rate-limited, or the dates exceed the 16-day forecast horizon, the application still generates and persists the itinerary. The response returns:
  - `"weather": null`
  - `"warnings": ["weather_unavailable: Weather forecast could not be retrieved; itinerary generated with seasonal estimates."]`

## 7. API Route Endpoints

### 1. Create Trip (`POST /api/trips`)
- **Status**: `201 Created`
- **Request Body**: `TripRequest`
- **Workflow**:
  1. Validate incoming `TripRequest` schema.
  2. Call Open-Meteo geocoding to resolve `destination` coordinates.
  3. Attempt Open-Meteo weather forecast fetch.
  4. Execute deterministic itinerary generator matching pace, duration, and interests.
  5. Persist trip record to PostgreSQL via SQLAlchemy.
  6. Return complete `TripResponse`.

### 2. Get Trip by ID (`GET /api/trips/{id}`)
- **Status**: `200 OK` (or `404 Not Found`)
- **Response Body**: `TripResponse`
- **Workflow**: Loads persisted trip from database without re-executing external API calls.

### 3. List Trips (`GET /api/trips?limit=10&offset=0`)
- **Status**: `200 OK`
- **Query Parameters**: `limit` (int, default 10, max 50), `offset` (int, default 0).
- **Response Body**: List of summarized trip metadata (`id`, `destination`, `start_date`, `end_date`, `created_at`).

## 8. End-to-End User Journey

```text
[1. Intake Form] ----(POST /api/trips)----> [2. Backend Generation]
       |                                              |
       v                                              v
[Input Validation]                          [Geocode -> Weather -> Itinerary -> DB]
       |                                              |
       v                                              v
[3. Result Page] <---(Redirect /trips/[id])-- [Persisted Trip ID]
       |
       +--(Direct Browser Reload)-----------> [GET /api/trips/{id}]
```

1. **User Intake**: User specifies origin, destination, dates, party size, optional budget, and interests in the frontend UI.
2. **Deterministic Processing**: Backend validates input, geocodes destination, retrieves weather (or degrades gracefully), builds the itinerary, and persists the trip.
3. **Results View**: Frontend displays the trip itinerary with daily breakdowns, weather widgets, provenance tags, and citations.
4. **Reloadability**: User can bookmark or refresh `/trips/[id]` at any time to inspect their saved plan directly from the database.
